# S6a：逐查询指标、分层汇总与独立标量审计

日期：2026-11-12。此阶段是S6报告器的第一部分，**不代表S6或Phase 3A全量评测完成**。仅运行小型文件夹具，未训练、未评价holdout、未在真实608窗口上新增全量评分。

## 解决的问题

S3–S4分别实现了指标并做有界验证，S5实现了统一原始预测发布格式，但尚无统一入口将保存的预测映射回共享GT并输出可核对的查询级数据及分层统计。本轮新增 `evaluation/scenario_report.py`、`scripts/build_scenario_query_report.py` 和相应测试，先打通这一基础链路。

报告直接使用S5的不可变预测，不重新生成噪声或训练模型。开始前验证发布凭据、GT来源和全部冻结预测；每个角色读取一次共享GT，通过gt_index恢复原观测流顺序，逐策略处理预测分片。报告标识绑定上游身份、完成凭据哈希和当前报告/指标源码。运行末尾再核对上游文件与源码，防止读取期间来源改变。

## 独立核对方法

向量实现之外，使用Python循环、math.hypot和明确的时间索引逐项重算全部M1/M2误差、方向投影/来源/有效性、剩余MR标记。汇总另用Python排序线性插值、math.fsum及键分组，核对均值、分位数、增益分类计数/比例/窗口宏比例、中位数、窗口/重复/查询分母，以及方向可评价计数、coverage和status/reason。

标量浮点比较采用rtol=atol=1e−12；离散mask、索引、计数精确比较。该容差只用于新指标独立实现间的浮点舍入差，未放宽父实验旧指标的精确兼容要求。

verify-only先从上游重放全部冻结预测（当前比计划要求的固定样本重放更严格），再从保存P/GT重算全部查询和汇总，执行标量核对并与已保存报告比较。它不只读取summary，也不只依赖文件哈希。即使统计被篡改并同步改写完成凭据中的哈希，仍会被语义重算拒绝。

## 验证与发现

新增测试覆盖同目标时间修正、分母守恒、缺失/重复噪声种子拒绝、无方向合法不可评价、窗口均值与log宏均值的区别、32分片端到端发布/验证、覆盖拒绝及重新哈希后的统计篡改。另故意注入错误向量指标、增益统计与方向计数/状态，确认独立审计能拒绝。

审查发现并修复两类问题：剩余MR遗漏逐k分母；只核对均值而遗漏增益分类和方向计数。均以标量参考和回归用例补齐。合成测试不能作为模型精度改善证据。
