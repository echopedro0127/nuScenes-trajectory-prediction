## 一、必须先修改的P1事项

### R1：查询步号与数组行号混用

位置：设计§4.2、M1/M2（55、67、75行），计划Task 2。

文档定义k=1至11，却直接写`P[k,j]`；实际预测数组第二维为零基，当前查询k应读`P[:,k-1,j,:]`。若照字面实现，不仅偏一位，还可能读取下一次观测后的预测。

建议唯一使用以下数组公式，若保留数学一基记号，另用不同符号且明确映射：

```text
j = k + m - 1
current  = P[:, k - 1, j, :]
previous = P[:, k - 2, j, :]   # 仅k>=2
E = norm(current - Y[:, j, :])
G = norm(previous - Y[:, j, :]) - E
```

已用数值夹具核对：k=2、m=2、j=3，数组row0该点误差3、row1误差1。正确增益为2；按原公式直接索引得到1，且读入row2。原计划的测试期望2是对的，设计公式需要与测试统一。

验收：查询k、数组row、目标j、绝对时间四列都输出；h=0.5/1/2s有效查询11/10/8、h=1s增益9对的测试保留。

### R2：输入契约遗漏GT历史和绝对时间来源

位置：设计§2/§4.2/§6，计划Task 4、Task 5。

实查父NPZ仅有`features/candidates/target/ca_allowed/guard_yaw/guard_min_speed`；records只有condition/instance/log/role/row/sample/scene/seed。**没有GT历史位置、history mask或anchor timestamp。**

影响：M4需要当前/历史GT方向，急刹/停车需要事件前速度，绝对事件ID需要时间；只读父NPZ无法完成。不能拿模型自己的速度特征当GT标签来源。

建议先补“数据装配契约”：

- 依据父run的`source_cache_root`加载相同角色的原轨迹缓存，按instance/sample键校验；row只作加速索引，不作唯一身份。
- 从sample元数据获得anchor timestamp，并与scene/log映射核对；固定偏移只在已验证的2Hz契约内使用。
- 保存history mask、GT历史/未来来源引用、坐标系、dt、原时间戳和每个字段的哈希/来源，不向模型传GT事件字段。
- 标签模块的GT输入与冻结模型输入分离；标签用GT、模型仍只用父特征/候选/保护trace。

验收：一个真实窗口能同时装配历史、未来、查询时间和身份，并证明与父候选一致；缺失字段明确报错，不能补GT到观测流。

若采纳R4、把3A收缩为窗口级标签，可先使用window key+relative step；绝对时间/完整episode装配留3B。GT历史来源仍是3A的必要依赖，不能一并省略。

### R3：分位数、比例与聚合分母没有唯一口径

位置：设计M1/M2/M3/M5，计划Task 6。

“先窗口均值”与“P95误差”目前可被理解成两种不同指标；恢复率未明确分母是否包括未受损事件，方向无定义也未确定是否只影响M4。

已验证歧义夹具：误差`[[0,0,10],[4,4,4]]`的逐查询P95为8.5，窗口均值P95约3.9667，含义明显不同。

建议写入统一聚合表：

| 指标 | 基本单位/有效性 | 建议主口径 |
| --- | --- | --- |
| M1平均误差 | 窗口×noise seed内的有效查询 | 先窗口均值，noise重复均权，再窗口均权；逐模型统计 |
| M1/M5尾部 | 固定lead的逐查询误差 | 主报`p95_query_error`；窗口均值P95如保留须另命名；固定quantile方法linear |
| M2比例 | 同目标时间的有效更新对 | beneficial/harmful/neutral共用分母，三者和为1；额外给窗口内比例再均值 |
| M3 AUC | 所有共同可评价的配对注入事件 | 保留未受损事件，不能只挑受损/已恢复事件 |
| M3恢复率 | 本模型的受损且可评价事件 | recovered/affected；未恢复率同分母；未受损率=unaffected/eligible |
| M3延迟均值 | 本模型已确认恢复的事件 | 必须同时给affected/recovered数，不能单独拿条件均值排名 |
| M4 | 标签方向有效的查询 | 仅排除该方向指标；不丢弃其M1/M2等结果 |
| log汇总 | 有可评价样本的log | 保留窗口均权总分及逐log均值；若报log宏平均须独立命名和计数 |

严格计数守恒：eligible=affected+unaffected，affected=recovered+not_recovered；不可评价另计。零分母输出null和状态，不输出0成功率。三训练seed在逐模型结果上统计，不在全部预测点上混算标准差。

## 二、建议补充的P2事项

### R4：真实数据集成验收太晚，episode范围前后矛盾

位置：设计§6（125行）、计划Task 4/Task 5（161、165行）。

现在Task 4要求绝对事件/episode，Task 5才装配父数据；同时设计说episode扩展在3B，计划却要求3A先完成合并。

建议把“一个真实窗口的冻结重放及旧指标兼容”放到数据契约之后，再完善纯指标。3A只保留窗口标签和抽查清单；episode归并放3B，或明确3A只做重复窗口标识，不宣传独立episode数量。

单纯按onset相距<=1s做传递闭包可能把0、0.8、1.6s的多个事件全串起来。3B应在原track时间轴上抽取canonical事件，再关联窗口；若仍窗口归并，须规定最大跨度、真实时间区间重叠、停止/再起步分隔及确定性合并算法。

### R5：缺失配对究竟报错还是跳过不一致

位置：计划Task 3“拒绝缺失配对”，Task 6“漏配对有明确状态”，设计M3“窗口不完整记不可评价”。

建议按原因分级：

- **完整性错误，终止运行：** 重复键、错GT、错角色/seed、缺预期checkpoint/配对条件、预测非有限、未声明的时间缺口。
- **统计不可评价，保留记录：** GT方向从未有效、已声明的事件缺少后续持续时间、零事件标签组、查询超出固定lead。
- v1输入契约本应有完整12点GT和11次预测；实际意外缺点不能默默当“正常删失”继续得到更好分数。

用`status/reason/valid_mask`区分，不以同一个NaN覆盖所有情况。内部缺失数组可用NaN+mask；导出JSON用null且禁止NaN/Infinity，CSV保留原因列。

### R6：事件标签的分段、时间对齐和状态边界不足

位置：设计§6/§7，计划Task 4。

需要补充：

1. 遇到低速/缺失方向应断开方向段；不得把停车前左转与停车后右转累加成同一S弯。
2. 明确速度区间、加速度和事件onset各对应哪个时间点，以及中值平滑的时间偏移；0.5s采样不能解释为毫秒级事件时刻。
3. 停车进入阈值0.3、起步阈值1.0之间的爬行如何标记；一开始静止不是新停车；预测窗末不足持续1s不能判未停车。
4. prior 2s不足、episode跨窗口边界、±pi方向跳变、标注抖动、恰好等于阈值都需要明确规则和测试。

首轮标签仍称candidate；人工pending不等于已确认。人工修改标签需保留原规则标签和修订来源，不能根据模型优劣改标签。

### R7：审计依赖的原始预测产物没有明确列出

位置：设计§9、计划Task 6/Task 7。

verify要求“从预测与GT重算”，但产物列表未明确保存P还是每次重新推理。仅保存新分数无法独立检查索引。

建议存按role/strategy分片的原始预测、查询step/目标列、身份键和GT引用；保存dtype/shape/hash，GT不必重复16次。16策略的float32预测总量约92,454,912字节（不含其他产物），可分片处理；这不是峰值RAM估计。

审计分两层：从不可变P重算全部指标；再对冻结模型重放固定样本并比对P。测试中提供慢速标量参考实现，不能只用同一向量函数再算一次来证明索引无误。

### R8：误差恢复不等于预测状态恢复

位置：设计M3。

例：GT=(0,0)，参考预测=(3,0)，受扰预测=(0,3)，两者L2误差都是3，因此A=0，但预测之间相差约4.243m。再如参考和受扰预测都很差，A也可能很小。

建议统一命名“额外位置误差恢复”，联合报告参考/受扰的绝对E_1s与AUC。不要据A=0声称离群影响已经消失或物理状态已恢复。若要研究预测回归基线，可另附`D=||P_outlier-P_reference||`，明确它是诊断，不替代GT准确性；首轮无需扩张为新总评分。

### R9：本机父链、批次和资源要求需要落到执行契约

位置：计划Task 5/Task 7。

父数据、权重不在公开Git文件中；只写相对路径不足以让其他环境复现。应列必需/可选资源、缺失错误和再生入口，显式记录父project root，不依靠固定目录深度猜所属源码。

旧指标精确比较依赖同一dtype、模型eval状态、CPU线程及原4096平坦批次路径。先复现再优化；换批次/后端后的容差若有必要须提前声明，不在验收失败后任意放宽。

父链验证每次运行执行一次并记录证明，不要每个策略/窗口递归跑一遍。按role/strategy处理，不堆叠所有模型/噪声/未来点到GPU；缓存读取避免在循环中反复解压同一NPZ。新评测纯单元测试不应依赖完整nuScenes或真实checkpoint。

## 四、必须覆盖的边界与异常清单

| 类别 | 边界/异常 | 应有行为 |
| --- | --- | --- |
| 时间索引 | k=1没有前次输出、末尾不足lead、非0.5s或乱序 | k=1无M2；尾部按契约排除；v1非规则输入拒绝 |
| 身份/来源 | 同名文件换模型、重复sample键、同row不同instance、角色/log重叠 | 完整性失败，不能按行号继续 |
| 输入数值 | shape错误、预测NaN/Inf、GT意外缺失、错误坐标单位 | 终止或按已声明GT状态处理，不丢坏预测来降低均值 |
| M2阈值 | G等于±0.05m、正负0、浮点边界 | 按固定严格不等式分类；断言容差不静默改变指标阈值 |
| 恢复 | 全窗未受损、延后受损、只有末点变好、恢复后复发 | 状态分开；至少两次稳定且窗内不复发 |
| 恢复 | 第二次离群step8、最后可用查询、短窗缺点 | 不把step8作为过去输入；不把窗末强制记恢复 |
| 恢复时间精度 | step4至7、两次确认且先受损 | 当前确认延迟仅1.0/1.5s或不可确认；AUC主指标，不伪造连续恢复分布 |
| 恢复语义 | 受扰误差偶然更小、两预测一样差、D很大但A=0 | 联合绝对误差解释，不能称物理状态恢复 |
| 分母 | affected=0、recovered=0、标签组为空、只剩1log | null和有效数；不填0成功率，不做显著性结论 |
| 尾部分布 | 尖峰被窗口均值抹平、少样本P99、seed混池 | 分别命名层级，固定quantile算法并报告计数 |
| 方向 | 静止、未出现有效方向、±pi跨界、低速乱向 | 只影响M4有效性；wrap角差、分段，不看未来补方向 |
| 停车/起步 | 初始静止、爬行、短停、未达到重启阈值、窗尾停车 | 单独状态/持续时间，不用最后点冒充停车 |
| S弯/掉头 | 净角抵消、停车前后反向转弯、无可靠方向段 | 在连续可靠段判定，不跨停车拼接S弯 |
| 标签 | prior历史不足、人工pending、规则/人工不一致 | candidate/不可评价/人工修订分别保存 |
| episode | 重叠窗口、链式<=1s合并、多个真实急刹 | 3B另定canonical事件，不扩大独立样本数 |
| 复现/资源 | 父产物缺失、路径移动、不同批次后端、重复解压 | 可操作的错误、明确环境/容差、角色分片读取 |

额外注意：预测目标时间晚于step8并不等于看到了step8观测；判定泄漏看输入到达时间。另一方面，GT事件标签可以用未来离线生成，但不应作为预测/保护/专家选择输入。
